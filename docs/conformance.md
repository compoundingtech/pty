# Conformance map

Generated by `cargo run -p pty-conformance --bin conformance-map`; do not edit by hand.

One row per Node test file (`tests/*.test.ts` in the Node checkout, 0.12.0+f005432). `kind` is how the suite is covered: `cli` (black-box through the binary), `protocol` (over the session socket), `unit` (pure logic, ported as crate unit tests), or `not-portable` (with the reason). A `cli`/`protocol` suite with no Rust file yet is still to do. Rust tests carry a `/// node: tests/<file>.test.ts:<line>` comment; the `tests` column counts them and the last column lists the Node lines they pin.

Run: `PTY_TEST_BIN=$(which pty) cargo test -p pty-conformance` (Node) and `cargo test -p pty-conformance` after `cargo build -p pty` (Rust). `scripts/conformance-both.sh` runs every file against both binaries and prints a side-by-side table plus `target/conformance/red.txt`, the tests that pass on Node and fail on Rust.
